* Introdução

O projeto *Gepis Dados Abertos* é uma iniciativa do grupo de pesquisa GEPIS voltada à coleta, processamento (ETL), análise estatística descritiva, visualização geoespacial e publicação colaborativa de bases de dados abertos brasileiros (como microdados do INEP/Censo Escolar, CNEFE e Malhas Territoriais do IBGE).


* Visão Geral do Projeto

- *Nome*: ~gepis-dados-abertos~
- *Identificador*: ~com.gepis.dadosabertos~
- *Tipo*: Aplicativo Desktop Híbrido (Tauri v2) e Aplicação Web (Angular)
- *Frontend*: Angular 20.3 com Angular Material, Plotly.js e Leaflet
- *Backend*: Rust (Edição 2021) com arquitetura modular desacoplada (Core Puro + Adaptadores Tauri IPC)
- *Plataforma*: Multiplataforma (Linux, Windows e macOS via Tauri)
- *Versão*: 0.1.2


* Arquitetura

O backend Rust segue princípios de *Arquitetura Limpa / Hexagonal* (detalhados em [[file:FASE1_BACKEND_MODULARIZATION.org][FASE1_BACKEND_MODULARIZATION.org]]):
- *Core Engine (~src-tauri/src/services/~ e ~src-tauri/src/models/~)*: Lógica de negócio 100% agnóstica ao Tauri, operando com tipos nativos do Rust para download assíncrono, descompactação ZIP, leitura de dicionários de dados em Excel, pipeline de dados em Polars, integração com APIs do IBGE (CNEFE e Malhas) e automação GitHub REST.
- *Adaptadores IPC (~src-tauri/src/commands/~)*: Comandos ~#[tauri::command]~ finos que resolvem caminhos do sistema operacional, emitem eventos de progresso para a interface Angular e delegam o processamento ao Core.
- *Persistência Atômica (~services/persistence/json_store.rs~)*: Armazenamento JSON genérico com escrita atômica e sincronização dual-write (ambiente de desenvolvimento e produção) para catálogos de datasets e histórico de análises.

** Pilha Tecnológica

- *Framework Desktop*: Tauri 2.0 (~tray-icon~, menus nativos, capabilities)
- *Frontend*: Angular 20.3, TypeScript 5.9, Angular Material, RxJS 7.8
- *Visualização de Dados e Mapas*: Plotly.js (~angular-plotly.js~) e Leaflet (~leaflet~)
- *Motor de Dados e ETL (Backend)*:
  - *Polars 0.41* (~lazy~, ~csv~) para agregações e filtragens de alto desempenho em grandes volumes de microdados
  - *Calamine 0.24* para leitura de dicionários de dados em planilhas Excel (~.xlsx~ / ~.xls~)
  - *CSV 1.3*, *Zip 2.3* e *Flate2 1.0* para ingestão e extração de arquivos compactados
- *Rede e Assincronismo*: Tokio 1.x + Reqwest 0.12 (~json~, ~gzip~, ~stream~)
- *Observabilidade*: ~tracing~, ~tracing-subscriber~ e ~tracing-appender~ com rotação de arquivos de log

** Plugins Ativados do Tauri

- ~tauri-plugin-http~ — Requisições HTTP assíncronas
- ~tauri-plugin-fs~ — Operações no sistema de arquivos local
- ~tauri-plugin-dialog~ — Diálogos nativos de seleção de arquivos e diretórios
- ~tauri-plugin-shell~ — Abertura segura de links externos (~https?://~)
- ~tauri-plugin-mcp-gui~ — Integração de inspeção e automação de interface

* Como Configurar, Construir e Executar

** 1. Configuração Automatizada do Ambiente

No *Fedora Linux*, execute o script de configuração na raiz do repositório para instalar pacotes de sistema (~webkit2gtk4.1-devel~, ~gtk3-devel~, ~libxdo-devel~, etc.), dependências npm e realizar o build inicial do frontend:

#+BEGIN_SRC bash
./setup-fedora.sh
#+END_SRC

No *Windows*, utilize o script equivalente:

#+BEGIN_SRC cmd
setup-windows.bat
#+END_SRC

*** Instalação Manual de Pré-requisitos (Fedora Linux)

Caso prefira instalar manualmente as dependências de sistema no Fedora:

#+BEGIN_SRC bash
sudo dnf install -y \
    glib2-devel \
    gtk3-devel \
    webkit2gtk4.1-devel \
    libsoup3-devel \
    openssl-devel \
    libxdo-devel \
    librsvg2-devel \
    gcc \
    gcc-c++ \
    pkg-config \
    rustfmt \
    clippy
#+END_SRC

** 2. Variáveis de Ambiente (~.env~)

Para habilitar o preenchimento automático das credenciais de colaboração com o GitHub (criação automatizada de branches e envio de Pull Requests com novas análises):

#+BEGIN_SRC bash
cp .env.example .env
# Edite o arquivo .env informando GITHUB_USERNAME, GITHUB_TOKEN, GITHUB_OWNER e GITHUB_REPO
#+END_SRC

** 3. Comandos de Desenvolvimento e Build

Os scripts principais de desenvolvimento ficam em ~angular-ui/package.json~:

#+BEGIN_SRC bash
cd angular-ui

# Desenvolvimento completo (Angular em modo watch + janela desktop Tauri com hot-reload)
npm run tauri:dev
# (ou seu alias equivalente: npm run start:dev)

# Apenas servidor web Angular (http://localhost:4200)
npm run start

# Compilação apenas do frontend Angular
npm run ng-build-dev       # Build de desenvolvimento (gera www/browser)
npm run ng-build-homolog   # Build de homologação
npm run ng-build-prod      # Build de produção

# Build completo do aplicativo Desktop para produção (gera binário e instaladores)
npm run tauri:prod

# Compila para produção e inicia o binário gerado imediatamente
npm run start:prod
#+END_SRC

Também é possível invocar o Tauri diretamente a partir da raiz do projeto:

#+BEGIN_SRC bash
npx tauri dev
npx tauri build
#+END_SRC

** 4. Monitoramento de Logs em Tempo Real

A aplicação grava logs detalhados no diretório de dados do usuário (~~/.local/share/com.gepis.dadosabertos/logs/~ no Linux ou ~%APPDATA%~ no Windows). Para acompanhar os logs em tempo real:

#+BEGIN_SRC bash
# Linux / macOS
./tail-log.sh

# Windows (PowerShell)
.\tail-log.ps1
#+END_SRC

** 5. Desenvolvimento no Emacs (~init.el~)

O repositório inclui um arquivo ~init.el~ autocontido na raiz, pré-configurado para desenvolvimento em Rust (~rust-mode~, ~cargo~, ~eglot~ + ~rust-analyzer~, ~corfu~, ~vertico~, ~magit~ e ~treemacs~), mantendo todos os pacotes isolados em ~.emacs-cache-gepisopendata/~:

#+BEGIN_SRC bash
emacs -q -l ./init.el
#+END_SRC
